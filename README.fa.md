# مهر — ۰٫۲٫۱، نامزد انتشار

فایل‌های نصب و گزارش‌های آزمون از GitHub Actions همین مخزن دریافت می‌شوند. وجود workflow به‌تنهایی نشانه موفقیت بیلد نیست.

تطبیق بندبه‌بند قابلیت‌ها، شواهد و محدودیت‌ها در `FEATURES.fa.md` است. پیش‌نویس هر گفتگو جدا و رمزگذاری‌شده نگه داشته می‌شود. هنگام ورود بدون پشتیبان و پس از تغییر رمز، ذخیره پشتیبان تازه یادآوری می‌شود. پشتیبان را در محل مستقل از برنامه نگه دارید؛ قدیمی‌بودن پشتیبان می‌تواند باعث از دست‌رفتن پیام‌ها و تازه‌سازی نشست شود.

## سرور

بسته را کامل استخراج کنید. ویندوز سرور: `deploy/install-windows-relay.ps1` با Administrator؛ شروع خودکار با Scheduled Task است. اوبونتو: `sudo bash deploy/install-ubuntu-offline.sh`؛ کاربر سرویس و systemd ساخته می‌شود. نصب‌کننده‌ها از فایل اجرایی همراه استفاده می‌کنند و هنگام نصب به pip نیاز ندارند. اجرای دستی:

```sh
./dist/MehrRelay --host 0.0.0.0 --port 8787 --data relay-data
```

در ویندوز از `dist/MehrRelay.exe` استفاده کنید. TCP 8787 را در فایروال باز کنید. IP قابل‌دسترسی داخل کشور و مقدار pin از `relay-public.json` را با مسیر مطمئن به کاربران بدهید. pin نسخه ۰٫۲ کلید X25519 انتقال است و با نسخه ۰٫۱ تفاوت دارد. کلید انتقال سرور قادر به بازکردن پیام‌های سرتاسری نیست.

سرور نصب‌شده ویندوز با حساب محدود Local Service اجرا می‌شود؛ کد نصب‌شده برای آن فقط خواندنی و پوشه داده قابل‌نوشتن است. نصب‌کننده برای تنظیم task و فایروال به Administrator نیاز دارد. برای ارتقا، پس از تهیه پشتیبان پوشه داده سرور، نصب‌کننده نسخه تازه را دوباره اجرا کنید؛ فرایند سرور با فایل جدید راه‌اندازی و کلید pin قبلی حفظ می‌شود. در اوبونتو نیز اجرای مجدد نصب‌کننده، سرویس را با فایل تازه راه‌اندازی می‌کند.

پنل مدیر فقط روی خود سرور: `http://127.0.0.1:8788`؛ رمز در `admin-token.txt` پوشه داده است. پورت مدیریت را عمومی نکنید. ارسال فایل پیش‌فرض خاموش و از این پنل قابل‌فعال‌سازی است.

## کلاینت

کل پوشه `dist/MehrChat` را نگه دارید. ویندوز: `MehrChat.exe`؛ نصب اختیاری با `deploy/install-windows-client.ps1`. لینوکس: `dist/MehrChat/MehrChat` یا `bash deploy/install-linux-client.sh`. لینک‌ها و کتابخانه‌های همراه را حذف نکنید. حذف کلاینت با `deploy/uninstall-windows-client.ps1` یا `bash deploy/uninstall-linux-client.sh` انجام می‌شود و فایل هویت باقی می‌ماند.

۱. نام کاربری انگلیسی، نام نمایشی و رمز حداقل ۱۲ نویسه بسازید.
۲. از منو، «سرورها»، IP و پورت و pin را وارد کنید؛ تا ۵ رله هم‌زمان. ذخیره، اتصال‌ها را دوباره برقرار می‌کند.
۳. کارت عمومی مخاطب را وارد یا نام او را هنگام آنلاین‌بودن جستجو کنید. اثرانگشت را مستقل، مثلاً در ملاقات یا تماس قابل‌اعتماد، مقایسه کنید؛ از کنار همان کارت کپی نکنید.
۴. آغاز اولین نشست نیازمند مشارکت هر دو طرف است. رله کارت عمومی را روی دیسک نگه نمی‌دارد. پس از ساخت نشست، صف رمزگذاری‌شده تحویل آفلاین را فراهم می‌کند.
۵. گروه از مخاطبان تأییدشده ساخته می‌شود. سازنده نام و اعضا را تغییر می‌دهد. معرفی کارت توسط سازنده فقط اعتماد در محدوده گروه است و مخاطب خصوصی تأییدشده ایجاد نمی‌کند.
۶. در اطلاعات گفتگو، حذف خودکار پیام‌های جدید را روی ۱ ساعت، ۱ روز، ۷ روز یا ۳۰ روز بگذارید؛ فایل هم همین زمان را دارد.
۷. دکمه کنار پیام برای حذف همه و ذخیره فایل است. در خصوصی هر دو طرف، در گروه فقط فرستنده همان پیام اجازه حذف دارد. رسید تحویل با رسید خواندن فرق دارد.

نام کاربری در هر رله مستقل و بدون حساسیت به حروف بزرگ/کوچک رزرو می‌شود. قفل برنامه شبکه را متوقف می‌کند و پیام‌ها تا بازکردن حساب در صف می‌مانند؛ Push خارجی وجود ندارد. فایل‌پیکر اندروید می‌تواند عملیات انتخاب فایل را ادامه دهد؛ پس از بازگشت محدودیت بیکاری بررسی می‌شود.

## نگهداری کلید

ویندوز: `%APPDATA%/MehrChat/identity.mcv`؛ لینوکس: `~/.local/share/MehrChat/identity.mcv`. نصب‌کننده/حذف‌کننده همراه این داده را پاک نمی‌کند؛ حذف پروفایل یا داده می‌تواند آن را از بین ببرد.

**اندروید هنگام uninstall داده خصوصی را حذف می‌کند.** قبل از حذف، پشتیبان رمزگذاری‌شده را در Documents یا محل مستقل ذخیره کنید و پس از نصب، پیش از ساخت حساب بازیابی کنید. بدون پشتیبان و رمز بازیابی ممکن نیست. یک هویت را هم‌زمان روی دو نصب فعال نکنید. پشتیبان قدیمی ممکن است به تازه‌سازی نشست نیاز داشته باشد؛ پیام‌های در مسیر الزاماً بازیابی نمی‌شوند. تغییر رمز، پشتیبان قدیمی را دوباره رمزگذاری نمی‌کند.

در اندروید، مرحله پشتیبان اولیه با زدن بیرون کادر یا لغو فایل‌پیکر رد نمی‌شود؛ فایل را در Documents محلی و مستقل ذخیره کنید یا حساب را قفل کنید. این فایل را حذف نکنید و با تغییرات مهم حساب، پشتیبان تازه بگیرید. فایل‌پیکر هر گوشی باید روی دستگاه واقعی نیز بررسی شود.

## اندروید و امضا

APK دارای debug برای آزمون نصب است. release-unsigned بدون قابلیت دیباگ ساخته می‌شود و پیش از نصب باید با کلید خودتان امضا شود. کلید را خارج از مخزن نگه دارید. با SDK build-tools و متغیرهای `ANDROID_SDK_ROOT` و `MEHRCHAT_KEYSTORE_PASSWORD`:

```sh
bash scripts/sign_android.sh unsigned.apk /private/mehrchat.jks alias signed.apk
```

کلید یا رمز انتشار ثابت داخل پروژه نیست. نسخه اصلی arm64-v8a، حداقل Android 8 / API 26 و هدف API 35 است؛ x86_64 برای شبیه‌ساز ساخته می‌شود. شبیه‌ساز جای گوشی واقعی و بررسی فایل‌پیکر و صفحه‌کلید سازندگان مختلف را نمی‌گیرد.

## شبکه و امنیت

هیچ وابستگی اجرایی ضروری به Firebase، CDN، فونت آنلاین، DNS خارجی، STUN خارجی یا گواهی SSL وجود ندارد. IP رله را مستقیم وارد کنید؛ مسیر داخلی هر دو اپراتور به رله باید باز باشد. کارکرد در تمام محدودیت‌های شبکه تضمین نشده است.

حذف و انقضا روی کلاینت سازگار و صف رله اجرا می‌شود؛ اسکرین‌شات، فایل صادرشده، نسخه ذخیره‌شده گیرنده و پشتیبان قدیمی قابل‌پس‌گرفتن نیستند. ساعت دستگاه‌ها باید درست باشد. نرم‌افزار هنوز ممیزی مستقل نشده است؛ `SECURITY.md` حدود را توضیح می‌دهد.

## ساخت

```sh
python -m pip install -r requirements.txt
python main.py
python -m unittest discover -s tests -v
python -m pip install pyinstaller==6.22.3
python scripts/build.py server
python scripts/build.py client
```

اندروید روی لینوکس با Java 17، Rust، SDK/NDK و Buildozer: `buildozer android debug` و `buildozer android release`. اولین ساخت به دانلود ابزارها نیاز دارد؛ اجرای بسته ساخته‌شده به آن دانلودها وابسته نیست. نسخه‌ها و recipeهای بومی در مخزن هستند.


## نصب تعاملی جدید اوبونتو و کلاینت اختصاصی

از سورس پروژه روی اوبونتو ۲۴٫۰۴ اجرا کنید:

```sh
sudo bash deploy/install-ubuntu.sh
```

نام کاربری و رمز مدیر، تأیید یا اصلاح IP قابل‌دسترسی، دامنه اختیاری و دریافت اختیاری گواهی عمومی پرسیده می‌شود. تنظیم DNS و بازکردن پورت‌ها با مدیر سرور است. حتی بدون دامنه یا در صورت شکست دریافت گواهی عمومی، TLS با CA اختصاصی فعال می‌ماند؛ گواهی و نام میزبان در کلاینت بررسی می‌شوند. تایمر روزانه تمدید و جایگزینی گواهی را انجام می‌دهد. CA خصوصی را امن پشتیبان بگیرید و پوشه داده سرور را هنگام ارتقا حفظ کنید. CA ده سال اعتبار دارد؛ قبل از انقضای آن باید اعتماد کلاینت‌ها به‌روز شود.

پنل مدیریت فقط روی 127.0.0.1:8788 است و پس از نصب جدید، نام کاربری و رمز انتخاب‌شده را می‌خواهد. فایل عمومی `client-profile.json` در پوشه داده سرور برای واردکردن در کلاینت اصلی صادر می‌شود. کلاینت ابتدا اتصال و هویت سرور را بررسی می‌کند و بعد صفحه ورود را نشان می‌دهد. پیش‌فرض 127.0.0.1:8787 برای سرور محلی است؛ سرویس عمومی آماده‌ای معرفی نشده است.

با نصب و ورود به GitHub CLI می‌توان از همان نصب‌کننده ساخت اختصاصی ویندوز و اندروید را درخواست و دریافت کرد. ساخت روی runner مناسب هر سیستم انجام می‌شود. در رابط نسخه اختصاصی آدرس نمایش داده نمی‌شود؛ نسخه، پروتکل و وضعیت TLS نمایش داده می‌شود. آدرس از روی ترافیک یا بررسی برنامه قابل کشف است. APK دیباگ قابل نصب آزمایشی است؛ APK ریلیز به امضای مالک نیاز دارد. جزئیات در README انگلیسی آمده است.
